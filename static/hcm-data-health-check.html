The 30 Checks

Every Module. Every Critical Data Pattern.

Grouped by module. Severity-rated. Each check includes the SQL, the row count, and a remediation recommendation.

Core HR — PER_* Tables
8 checks
  • ›Assignment orphans (no parent person)
  • ›Effective date gaps in assignment history
  • ›Duplicate national identifiers (SSN/NI/TFN)
  • ›Active assignments with no work relationship
  • ›Missing _TL translation rows (blank display names)
  • ›Invalid lookup code references in PER tables
  • ›Overlapping date-effective rows per person
  • ›Positions without a valid grade or job attached
Payroll — PAY_* Tables
6 checks
  • ›Active employees with no payroll assignment
  • ›Terminated employees with active payroll
  • ›Element entries with no parent element link
  • ›Costing segments that don't map to valid GL codes
  • ›Payroll assignments with mismatched legislation
  • ›Direct deposit bank records missing after enrollment
Absence — ANC_* Tables
5 checks
  • ›Absence entries with no matching plan enrollment
  • ›Accrual balances exceeding plan maximum
  • ›Absence entries spanning invalid date ranges
  • ›Employees enrolled in plans with expired effective dates
  • ›Missing accrual balance rows for enrolled employees
Compensation — CMP_* Tables
5 checks
  • ›Salary records with no parent assignment
  • ›Pay proposals with missing action owner
  • ›Grade steps that fall outside the valid grade ladder
  • ›Compensation change rows with overlapping dates
  • ›Salary ranges where min > max (corrupt grade rate)
Recruiting — IRC_* Tables
4 checks
  • ›Offers without a parent requisition
  • ›Candidates in "Hired" status with no worker record created
  • ›Requisitions with target hire date before posting date
  • ›Duplicate candidate submissions on same requisition
Security & Access — FND_* / HRC_*
2 checks
  • ›Terminated employees with active application user accounts
  • ›Security role assignments referencing deleted persons

FAQ

Common Questions

What Oracle access do you need?

A read-only reporting account that can run queries in Oracle BI Publisher, SQL Workshop (via Reports and Analytics), or a BIP data model connection. We do not need DBA access, schema-level access, or the ability to modify any data. The access is the same level needed to run OTBI reports.

Will this affect our production environment?

No. Every query is a SELECT statement — read-only, no inserts, no updates. We run during off-peak hours by default and can coordinate with your team's window if needed.

What Oracle Fusion versions does this cover?

Oracle Fusion HCM Release 13 (current cloud) through Oracle 24B, including the PER_ALL_ASSIGNMENTS_M migration from earlier _F tables. We've tested these queries against Oracle 22D through 24B environments.

What if we're on Oracle EBS, not Fusion Cloud?

This service is specifically for Oracle Fusion HCM Cloud (SaaS). If you're on EBS, the table structures are different — email us and we can discuss whether an EBS-specific check makes sense for your environment.

How is this different from the free Data Quality Scanner?

The free scanner gives you 7 queries you run yourself. This service gives you 30 queries, run by an expert, with a full remediation report, SQL fix scripts, and a debrief call — delivered in 24 hours without your team needing to do anything except grant read access.

Is there a money-back guarantee?

Yes. If we can't find any issues in your environment — or if you find that our findings were inaccurate — we'll refund in full. In practice, we have never had a clean environment in hundreds of checks. The average instance has 12+ HIGH severity findings.
