OBIEE Assertion Failure pCriteria — Why It Happens and the Fix

Your OTBI report ran fine last week. Today it throws this:

OBIEE Error: Assertion failure: pCriteria
State: HY000. Code: 10058. [NQODBC] [SQL_STATE: HY000] [nQSError: 10058] A general error has occurred. [nQSError: 22025] pCriteria assertion failure.

The phrase "pCriteria assertion failure" is OBIEE's way of saying: something in your filter criteria is invalid logical SQL. The BI Server ran its pre-execution validation and rejected the query before it ever touched the database.

This guide covers every root cause — starting with the most common.

What Is pCriteria?

OBIEE decomposes every logical SQL query into named sections:

  • pSelect — the columns you're displaying
  • pCriteria — the filter/WHERE clause conditions
  • pOrderBy — sorting rules
  • pProjectionList — the full output column list

When you see "pCriteria assertion failure," OBIEE is saying: the filter expressions you wrote aren't valid in the logical SQL dialect. The fix is almost always to rewrite the filter using OBIEE-native syntax instead of Oracle physical SQL syntax.

Root Cause #1: Oracle SQL Functions in Filters

The most common trigger. You wrote an Oracle physical SQL function in your filter — TRUNC, SYSDATE, TO_DATE, NVL — that doesn't exist in OBIEE's logical SQL engine.

❌ Fails with pCriteria assertion:
-- This uses TRUNC and SYSDATE — Oracle physical SQL only WHERE "Employees"."HIRE_DATE" >= TRUNC(SYSDATE) - 90
✅ OBIEE-valid equivalent:
-- Use CURRENT_DATE instead of SYSDATE, TIMESTAMPADD instead of arithmetic WHERE "Employees"."HIRE_DATE" >= TIMESTAMPADD(SQL_TSI_DAY, -90, CURRENT_DATE)

The key function replacements for OBIEE filters:

Oracle Physical SQL OBIEE Logical SQL Equivalent
SYSDATE CURRENT_DATE
TRUNC(SYSDATE) CURRENT_DATE
SYSDATE - 30 TIMESTAMPADD(SQL_TSI_DAY, -30, CURRENT_DATE)
TO_DATE('2024-01-01', 'YYYY-MM-DD') DATE '2024-01-01'
NVL(column, 'default') IFNULL(column, 'default')
DECODE(col, 'A', 1, 'B', 2) CASE WHEN col = 'A' THEN 1 WHEN col = 'B' THEN 2 END
MONTHS_BETWEEN(d1, d2) TIMESTAMPDIFF(SQL_TSI_MONTH, d2, d1)

Root Cause #2: NULL Comparison Syntax

In Oracle SQL you can write WHERE column = NULL (though it never matches anything). OBIEE's logical SQL engine rejects this form entirely and throws a pCriteria assertion failure.

❌ Invalid in OBIEE:
WHERE "Assignments"."MANAGER_ID" = NULL WHERE "Assignments"."MANAGER_ID" != NULL
✅ Correct OBIEE syntax:
WHERE "Assignments"."MANAGER_ID" IS NULL WHERE "Assignments"."MANAGER_ID" IS NOT NULL

Root Cause #3: Subquery in the Filter Criteria

OBIEE does not support subqueries inside filter expressions. This is a hard limitation of the logical SQL layer. Any filter like WHERE col IN (SELECT ...) will trigger a pCriteria assertion failure.

❌ Not supported in OBIEE:
WHERE "Employees"."DEPARTMENT_ID" IN ( SELECT DEPARTMENT_ID FROM departments WHERE LOCATION = 'New York' )

There are two OBIEE-native approaches to replace subquery filters:

Option A — Use a Dashboard Prompt: Create a prompt that lets users select department IDs. The prompt feeds into the report filter as an explicit IN list, avoiding the subquery entirely.

Option B — Use a Narrative Filter with a Second Analysis: Run the subquery as a separate OTBI analysis, export the results as a list, and feed them as a static IN filter to your main report.

Best practice: Design your OTBI reports so all filter values come from prompts or are static. Any dynamic filtering that requires a correlated lookup should be handled at the subject area level by the OBIEE admin, not in the report criteria.

Root Cause #4: Invalid Column Reference Format

OBIEE requires columns in filter criteria to be referenced as "Subject Area"."Folder"."Column". If you reference a column with just its name, an alias, or a physical table name, the parser fails at pCriteria.

❌ Physical table reference (fails):
WHERE PER_ALL_PEOPLE_F.EFFECTIVE_LATEST_CHANGE = 'Y'
✅ Logical column reference (correct):
WHERE "Workforce Management - Worker Assignment Real Time"."Worker"."Effective Latest Change" = 'Y'

The column path must match the subject area's presentation layer exactly, including capitalization and spacing.

Root Cause #5: Report Changed After Subject Area Update

If an Oracle patch or quarterly update modified or removed a column from the subject area, saved filters that reference that column will trigger a pCriteria assertion failure when the report runs — even if the report definition hasn't changed.

How to identify this:

  1. Open the report in OTBI's Analysis Editor
  2. Check the Filters panel for any columns marked with a warning icon
  3. Columns that no longer exist in the subject area will be flagged
  4. Remove the invalid column from the filter and replace it with the updated column path
After Oracle quarterly updates: It's good practice to open and re-validate any business-critical OTBI reports. Subject area column names occasionally change across releases, especially in the Workforce Management subject areas.

Debugging Workflow

When you hit a pCriteria assertion failure, follow this sequence:

  1. Open the report in Edit mode → go to the Filters tab
  2. Look for warning icons — a yellow triangle means an invalid column reference
  3. Check each filter expression for Oracle SQL functions (TRUNC, SYSDATE, NVL, TO_DATE)
  4. Switch to Advanced SQL view — click the Advanced tab in the Criteria view to see the raw logical SQL. Inspect the WHERE clause.
  5. Test with all filters removed — if the report runs without filters, the issue is isolated to a specific filter. Add them back one at a time to find the culprit.

Full Rewrite Example: Active Employees Hired in Last 90 Days

❌ Physical SQL filter (will fail):
WHERE TRUNC(HIRE_DATE) >= TRUNC(SYSDATE) - 90 AND EMPLOYMENT_STATUS != NULL AND DEPARTMENT_ID IN (SELECT DEPT_ID FROM dept_table WHERE REGION = 'EMEA')
✅ OBIEE logical SQL filter (correct):
WHERE "Worker"."Hire Date" >= TIMESTAMPADD(SQL_TSI_DAY, -90, CURRENT_DATE) AND "Worker"."Employment Status" IS NOT NULL AND "Worker"."Department" IN ('Finance EMEA', 'HR EMEA', 'Operations EMEA')

Key changes:

  • Replaced TRUNC(SYSDATE) - 90 with TIMESTAMPADD(SQL_TSI_DAY, -90, CURRENT_DATE)
  • Replaced != NULL with IS NOT NULL
  • Replaced subquery with a static IN list (ideally driven by a dashboard prompt)
  • Used logical column paths instead of physical table.column references

Summary

OBIEE pCriteria assertion failures have five main causes:

  1. Oracle SQL functions in filters — replace TRUNC, SYSDATE, NVL with OBIEE equivalents
  2. NULL comparison with = — use IS NULL / IS NOT NULL
  3. Subqueries in filter expressions — use dashboard prompts or static IN lists
  4. Physical column references — use full "Subject Area"."Folder"."Column" paths
  5. Subject area columns removed after an Oracle update — remove and re-add the filter

The fastest way to isolate which filter is causing the failure: remove all filters, run the report, then add them back one at a time. The one that breaks the report is your culprit.
